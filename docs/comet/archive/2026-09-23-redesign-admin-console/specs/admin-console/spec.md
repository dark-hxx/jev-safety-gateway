# 管理控制台「最近请求」日志浏览

管理控制台（`web` SPA + `internal/admin`）为运营者提供网关配置、密钥管理与请求日志浏览。本规格描述归档后「最近请求」日志浏览的完整目标行为，包含筛选、服务端分页与列表布局。

## 日志查询 API

`GET /api/logs` 需要有效 bearer token（沿用 `auth` 中间件），返回符合条件的日志分页结果。

- 接受查询参数：
  - `limit`：单页条数，整数；取值范围与既有语义一致（超出 `[1,1000]` 或缺省时回退到默认 50）。
  - `offset`：跳过的记录数，非负整数；缺省或非法时按 0 处理。
  - `decision`：判定状态精确匹配，取值 `allow|block|skip|error`；空表示不限。
  - `model`：模型名子串匹配（SQL `LIKE`）；空表示不限。
  - `q`：关键词，对 `path`、`model`、`ip`、`reason`、`snippet` 做子串匹配（SQL `LIKE`）；空表示不限。
  - `since`：起始时间，unix 毫秒；仅返回 `ts >= since` 的记录；缺省或 ≤0 表示不限。
- 所有筛选条件之间为「与」关系，同时生效。
- 结果按 `id` 倒序（最新在前）。
- 响应体为对象：`{"items": LogEntry[], "total": number}`，其中 `total` 是在**不含 `limit`/`offset`** 前提下满足其余筛选条件的总记录数，`items` 是应用了 `limit`/`offset` 后的当前页记录。
- `LogEntry` 字段与结构保持不变（id/ts/method/path/kind/decision/score/model/latency_ms/ip/reason/snippet）。
- 所有参数使用参数化查询，不做字符串拼接，避免 SQL 注入。

Scenario: 分页与筛选组合查询
WHEN 客户端携带 `decision=block&q=1.2.3.4&limit=50&offset=50`
THEN 服务端返回第 2 页（跳过前 50 条）中 decision 为 block 且 path/model/ip/reason/snippet 命中 `1.2.3.4` 的记录，`total` 为满足该筛选条件的全部记录数。

Scenario: 缺省参数安全回退
WHEN 客户端不带任何参数请求 `/api/logs`
THEN 服务端返回按 id 倒序的首页（默认每页 50 条、offset 0）与 `total`，不报错。

## 筛选控件

「最近请求」卡片头部提供以下筛选控件，均为中文文案：

- 判定状态下拉：全部 / 放行 / 拦截 / 跳过 / 错误（沿用现有取值）。
- 模型输入框：按模型名子串筛选。
- 关键词输入框：按关键词子串筛选（覆盖路径、模型、来源 IP、原因、送检预览）。
- 时间范围下拉：全部 / 最近 1 小时 / 最近 6 小时 / 最近 24 小时 / 最近 7 天；前端换算为 `since` 毫秒时间戳。
- 刷新按钮：以当前筛选条件重新查询当前页。

Scenario: 改变筛选回到首页
WHEN 用户修改任一筛选控件的值
THEN 列表以当前全部筛选条件重新向 `/api/logs` 查询，并重置到第 1 页。

## 服务端分页浏览

- 每页固定 50 条。
- 卡片提供「上一页」「下一页」按钮，以及「第 X / 共 Y 页」与总条数指示（Y 由 `total` 与页大小计算）。
- 位于首页时「上一页」禁用；位于末页（或结果为空）时「下一页」禁用。
- 翻页时携带正确的 `offset` 与当前筛选条件向 `/api/logs` 查询。
- 通过翻页可浏览数据库中符合条件的全部历史日志，不受单次固定窗口限制。

Scenario: 边界翻页按钮状态
WHEN 结果共 3 页且当前处于第 1 页
THEN 「上一页」禁用、「下一页」可用；WHEN 翻到第 3 页 THEN 「下一页」禁用、「上一页」可用。

Scenario: 结果为空
WHEN 当前筛选条件无匹配记录
THEN 列表显示「暂无记录」，「上一页」「下一页」均禁用，页码显示为第 1 / 共 1 页或等价的空态。

## 列表布局

- 日志表格外层容器设有最大高度，行数超出时容器内部纵向滚动，页面整体不被撑开。
- 表头在容器内滚动时吸顶可见。
- 送检内容预览等字段保持 `escapeHtml` 转义，防止 XSS。
- 沿用现有暗色主题变量与表格样式，横向仍可在窄屏滚动。

Scenario: 高度受限内部滚动
WHEN 当前页记录较多超出容器最大高度
THEN 列表在容器内纵向滚动，表头吸顶，页面其他区域位置不被列表长度影响。

## 字体

控制台使用美观的系统字体栈，不依赖外部网络字体或内嵌字体文件，离线部署仍可用。

- 正文字体栈优先选择系统上可用的优质无衬线字体（如 Inter、系统 UI 字体、思源黑体 / Source Han Sans、苹方 / PingFang、微软雅黑 / Microsoft YaHei），并保留通用兜底（sans-serif）。
- 等宽内容（`.mono` 类，如时间、路径、密钥、IP）使用系统等宽字体栈（如 JetBrains Mono、SF Mono、Cascadia Code、Consolas、ui-monospace），并保留 monospace 兜底。
- 不通过 `<link>`/`@import` 引入 CDN 字体，也不 `go:embed` 字体文件；不新增网络请求。

Scenario: 离线可用的系统字体栈
WHEN 控制台在无外网的环境中加载
THEN 正文与等宽文本均使用本地系统字体栈渲染，不因缺少网络字体而发起外部请求或退化为默认衬线字体。

## Requirement: console-overview 管理控制台总览与规格取代

本能力定义重构后管理控制台的完整目标行为。管理控制台为 Vue 3 单页应用，构建产物经 `//go:embed` 打包进单个 Go 二进制，离线可用。

本规格上方以 `# 管理控制台「最近请求」日志浏览` 开头的段落及其后的 `## 日志查询 API`、`## 筛选控件`、`## 服务端分页浏览`、`## 列表布局`、`## 字体` 五节，是本能力 v1 的历史文本，由本规格的 Requirement 小节取代。其中「日志查询 API」定义的 `/api/logs` 参数语义，以及「字体」定义的离线系统字体栈，仍然有效，被本规格相应小节沿用。

`internal/proxy` 的过滤主链路行为不在本能力范围内：放行/拦截/跳过/错误的判定语义、`X-JEV-Gateway` / `X-JEV-Score` 响应头与 SSE 流式透传均保持不变，`logs` 表结构（表、列、现有索引）不变。登录与初始配置界面按 `docs/prototype/jev_3/code.html` 还原，其口令登录与初始设置行为不因本规格改变。
本能力允许的后端改动仅两处，均不触及过滤主链路：`internal/config` 中新增的只读聚合查询与 `GET /api/stats` 的响应字段扩展（见 `dashboard`，不新增 `/api/*` 路径），以及 `internal/admin` 静态文件服务的 SPA 回退（见 `app-routing`）。

## Requirement: offline-assets 静态资源与离线可用性

- 控制台由 Vue 3 + Vite + TypeScript + Tailwind 工程构建；源码与构建产物均提交入库。
- `go build -o gateway ./cmd/gateway` 直接产出包含完整控制台界面的二进制；构建阶段与运行阶段均不依赖 Node。
- 界面不引用任何公网资源：不通过 `<link>` / `@import` / `<script src>` 引入 CDN 上的样式、字体、图标或脚本。
- 字体使用系统字体栈，不内嵌字体文件，不新增网络请求。
- 视觉主题令牌以 `docs/prototype/cupertino_safety_gateway/DESIGN.md` 为基线落地：暗色调色板、8pt 间距体系、发丝边框、圆角与材质层级。
- 控制台仅在管理口（默认 `127.0.0.1`）提供；`/api/*` 除 `login` / `setup` / `setup-status` 外一律要求 bearer token。

Scenario: 离线加载不发外部请求
WHEN 控制台在无外网环境中加载并逐个访问登录页与三个业务界面
THEN 浏览器不发起任何指向公网域名的请求，界面样式、字体与图标均正常呈现。

## Requirement: console-shell 控制台壳与导航

- 控制台提供左侧导航，含三个条目：运行概览、网关安全配置、转发审计记录；另有顶部状态条展示网关启用状态与版本等既有信息。
- 导航条目由路由驱动，每个界面是独立的路由页面，详见 `app-routing`；切换不触发整页刷新。
- 未登录时展示认证入口视图；数据库未初始化时展示初始配置视图，两者按 `auth-entry` 小节还原，其口令登录与初始设置行为沿用现有接口与语义。
- 登录、初始设置与鉴权沿用现有接口与语义：`POST /api/login`、`POST /api/setup`、`GET /api/setup-status`；登录成功后凭 token 访问受保护接口，登出清除会话。

Scenario: 导航切换视图
WHEN 已登录用户在左侧导航点击「转发审计记录」再点击「运行概览」
THEN 主区域依次切换到对应视图，页面不发生整页刷新，当前登录状态保持有效。

## Requirement: app-routing 导航与路由

- 左侧导航由 `vue-router` 驱动，每个界面是独立的路由页面：独立视图组件 + 独立模块目录，视图切换走路由而非壳层内的条件渲染。
- 路由模式为 history（`createWebHistory`），三个业务界面分别位于 `/dashboard`、`/settings`、`/audit`；根路径与未匹配路径重定向到 `/dashboard`。
- 认证入口不占用业务界面的路由：未登录（或数据库未初始化）时展示认证视图，登录成功后进入目标路由。
- 管理口的静态文件服务为单页应用提供回退：非 `/api/` 前缀且未命中静态文件的 GET 请求回退到 `index.html`，使深链接直接打开与刷新不返回 404。该回退只影响静态文件服务，不新增 `/api/*` 路径、不改 `logs` 表、不改 `internal/proxy`。
- 新增界面只需注册一条路由与一个模块目录，无需改动壳层、现有界面与认证入口。

Scenario: 深链接直达与前进后退
WHEN 已登录用户直接在地址栏打开 `/audit` 并刷新页面
THEN 控制台加载后渲染转发审计记录界面而非 404，左侧导航中「转发审计记录」呈选中态；WHEN 用户随后点击浏览器后退 THEN 回到上一个访问过的界面。

Scenario: 新增界面不改动壳层
WHEN 在路由表中新增一条路由与对应模块目录
THEN 左侧导航按新路由渲染条目并可切换，壳层、现有三个业务界面与认证入口的代码均无需修改。

## Requirement: auth-entry 登录与初始配置

未登录时（或数据库未初始化时）展示的认证入口界面，按 `docs/prototype/jev_3/code.html` 还原结构与交互。认证流程沿用现有接口与语义，本能力只改变该界面的呈现方式。
- 布局：居中认证卡，最大宽度 440px，使用半透明容器材质与背景模糊、`rounded-xl` 圆角与高阴影层级；卡片背后有主色与副色的环境光晕。
- 卡片内容自上而下：App 图标（仓库内本地内联 SVG 素材，带渐变光环）、居中标题「JEV 安全网关」与副标题「AI Request Security & Filtering Gateway」、动态状态胶囊、口令表单、守护进程状态胶囊、三条安全徽标、页脚。
- 动态状态胶囊：登录模式使用主色底、锁形图标与「输入管理员口令以访问控制台」；初始配置模式使用第三色底、注册图标与「首次使用：请设置管理员口令（至少6位）」。

- 无后端来源的元素以可识别的「未接入」降级态呈现且不显示伪造数值：版本徽标（无 `/api/version`）、延迟徽标、守护进程地址胶囊。`ZERO-TRUST TLS` 与 `PII SHIELD ACTIVE` 是静态标语，保留原文。
- 口令哈希元信息如实标注为 bcrypt，不标注 `SHA-256` 或 `Argon2id`。
- 不呈现「保持本工作站受信任凭据 (24h)」勾选项，不提供语言切换控件；界面文案为中文。
- 认证行为不回退：口令长度不少于 6 位；初始配置要求两次输入一致；`POST /api/login`、`POST /api/setup`、`GET /api/setup-status` 的语义与既有实现一致；`/api/*` 除 `login` / `setup` / `setup-status` 外一律要求 bearer token。

Scenario: 已初始化时进入验证登录模式
WHEN 数据库已初始化且未登录用户打开控制台
THEN 展示验证登录模式的认证卡（主色状态胶囊、锁形图标、「输入管理员口令以访问控制台」、无确认口令字段、「登录控制台」主按钮），分段控件中「初始配置」呈禁用态。

Scenario: 未初始化时进入初始配置模式
WHEN 数据库尚未初始化且用户打开控制台
THEN 展示初始配置模式的认证卡（第三色状态胶囊、注册图标、「首次使用：请设置管理员口令（至少6位）」、出现「重复确认新口令」字段、「完成设置并进入」主按钮），提交发往 `POST /api/setup`，分段控件中「验证登录」呈禁用态。

Scenario: 登录页无来源元素降级
WHEN 未登录用户打开登录页
THEN 版本徽标、延迟徽标与守护进程地址胶囊标注「未接入」且不显示数值；页面不出现语言切换控件与「保持本工作站受信任凭据 (24h)」勾选项；口令哈希元信息标注为 bcrypt。

Scenario: 口令校验与主流程
WHEN 用户在初始配置模式输入不足 6 位的口令，或两次输入不一致
THEN 界面以浮动提示给出对应错误且不发出请求；WHEN 校验通过后提交 THEN 请求发往 `POST /api/setup`，成功后进入控制台主界面。

## Requirement: dashboard 运行概览（驾驶舱）

- 概览视图顶部展示统计卡片，数据来自 `GET /api/stats`（支持 `hours` 参数）与 `GET /api/state` 返回的 `stats24h`：总数、放行、拦截、跳过、错误五类计数为真实值。
- 提供时间范围分段控件（1 小时 / 6 小时 / 24 小时 / 7 天），切换后以对应 `hours` 重新查询统计并重绘两张图表。
- 趋势图「流量与安全威胁态势」绘制入站总量、安全放行、拦截三序列，数据来自 `GET /api/stats` 响应中新增的 `bucket_seconds` 与 `series`：`series` 逐桶给出 `{ts, total, allowed, blocked}`，覆盖 `[now-hours, now]` 的每一个桶，空桶计数为 0；分桶粒度由后端按 `hours` 确定性推导并在响应中回传，前端只渲染，不自行分桶、不插值出无来源的数据点。
- 「风险分值分布」绘制区间内 `score` 非空记录的分值直方图，数据来自同一响应中新增的 `score_buckets` 与 `unscored`：`score_buckets` 为 0.2 步长的 5 档（`[0,0.2)` … `[0.8,1.0]`，末档含 1.0），`unscored` 为区间内 `score` 为空（跳过或 JEV 未返回分值）的记录数；卡片标注实际样本量。统计口径为区间内**全部已送检记录**，而非仅拦截记录——拦截的判定条件本身就是分值越过阈值，只统计拦截记录会使分布退化到阈值一侧的单一档位。
- `GET /api/stats` 的既有字段与语义保持不变，新增字段只增不改；不新增 `/api/*` 路径、不改 `logs` 表结构与 `internal/proxy` 埋点。新增聚合为只读查询，复用现有 `idx_logs_ts` 索引。
- 提供前往网关配置与转发审计记录的快捷入口，点击后切换到对应视图。
- 原型中其余缺少后端数据来源的元素——多集群节点与地理位置、Token 估算、集群 SLA 与网关开销等——一律以明确标注的降级态呈现（占位形态 + 可识别的「未接入」提示），不得显示无来源的数值。

Scenario: 统计卡片展示真实计数
WHEN 已登录用户进入运行概览视图
THEN 统计卡片展示 `/api/stats` 与 `/api/state` 返回的真实计数，且与转发审计记录中相同条件下的记录数一致。

Scenario: 趋势图按后端分桶序列绘制
WHEN 用户在概览视图把时间范围从「24 小时」切换为「7 天」
THEN 控制台以 `hours=168` 重新查询 `/api/stats`，按响应中的 `bucket_seconds` 与 `series` 重绘三序列曲线；各桶计数与 `/api/logs` 同区间记录逐桶一致，空桶为 0。

Scenario: 风险分值分布与样本量一致
WHEN 已登录用户进入运行概览视图
THEN `score_buckets` 五档计数与 `unscored` 之和等于同区间 `/api/logs` 的记录总数，卡片标注的样本量为区间内 `score` 非空的记录数。

## Requirement: gateway-settings 网关与安全策略配置

- 配置视图按三个分组组织表单：上游服务与 JEV 检定路由、安全防护与自动拉黑策略、调用密钥池分发。
- 表单字段与现有 `Settings` 一致并可读写：经 `GET /api/settings` 读取，经 `PUT /api/settings` 保存；保存后重新加载仍为保存值。
- 密钥池经 `/api/keys` 及其子路径管理：列出密钥、新增密钥、启用/停用、删除。
- 阈值一类数值控件与当前值保持同步显示，取值范围与后端校验一致。
- 原型中出现但现有后端无对应字段或接口的控件（连通性测试、密钥健康成功率、分发池负载、WORM 合规归档与校验码等）以明确标注的降级态呈现或不呈现，不得提交无效字段、不得显示无来源数值。

Scenario: 保存设置后重新加载仍生效
WHEN 用户修改安全判定阈值并保存，随后刷新控制台

## Requirement: audit-stream 转发审计记录

- 审计视图经 `GET /api/logs` 查询，沿用既有参数语义：`limit`、`offset`、`decision`、`model`、`q`、`since`，响应为 `{items, total}`。
- 提供判定状态、模型、关键词、时间范围四类筛选控件；改变任一控件后以当前全部筛选条件（「与」关系）重新查询并重置到第 1 页。
- 列表按服务端分页展示，显示「第 X / 共 Y 页」与总条数，提供上一页/下一页；位于首页时上一页禁用，位于末页或结果为空时下一页禁用，无匹配时显示空态。
- 表格容器设有最大高度，超出时容器内纵向滚动且表头吸顶。
- 列表展示 `LogEntry` 已持久化字段：时间、方法、路径、判定、分值、耗时、来源 IP、模型、原因、送检摘要；文本保持 HTML 转义，防止 XSS。
- 提供详情抽屉，展示单条 `LogEntry` 的全部已持久化字段。
- 原型中依赖缺失后端的列与操作——地理位置、处置规则矩阵、全局请求唯一 ID、完整原始请求体、耗时分解、Token 估算与风险级、导出 CSV、加入黑名单、重放测试——以明确标注的降级态呈现或不予呈现，不得显示无来源数值、不得执行无后端支撑的操作。

Scenario: 筛选与分页不回退
WHEN 用户在第 3 页将判定状态改为「拦截」并追加模型筛选
THEN 控制台携带当前全部筛选条件与 `offset=0` 重新请求 `/api/logs` 并回到第 1 页，列表显示符合条件的结果与正确的 `total`。

Scenario: 详情抽屉展示已持久化字段
WHEN 用户点击列表中的任意一条记录
THEN 详情抽屉打开并展示该条记录的全部已持久化字段，未持久化的字段以明确标注的降级态呈现而非空值或占位数值。
